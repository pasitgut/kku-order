# หน้า "บุคลากรโดยตำแหน่ง" (design แบบสั้น)

วันที่ 15 พ.ย. 2026 · ขนาดงาน: เปลี่ยนเล็ก (endpoint ใหม่ 1 ตัว และหน้าใหม่ 1 หน้า)

## เจตนา

ลูกค้าใช้ระบบแบบนี้: อัปโหลดเอกสาร → OCR อัตโนมัติ → ค้นหารายชื่อที่ OCR ดึงได้ทันที แต่ตำแหน่งบริหารมีวาระ คนที่ดำรงตำแหน่งเปลี่ยนไปตามเวลา หน้านี้มีไว้สองอย่าง

1. เช็คว่าแถว "โดยตำแหน่ง" ในเอกสารที่ OCR ดึงมา ผูกกับผู้ดำรงตำแหน่งคนล่าสุดถูกคนหรือไม่
2. ดูให้เร็วว่าตอนนี้ใครดำรงตำแหน่งอะไร หน้าต้องไม่รก มีรายละเอียดเท่าที่จำเป็น

## เป้าหมาย

- แสดงตำแหน่งบริหารทุกตำแหน่งที่มีผู้ดำรงอยู่ ณ วันนี้ (เวลา Asia/Bangkok)
- คนที่แสดงต้องเป็นคนเดียวกับที่ระบบผูกให้แถวโดยตำแหน่งในเอกสารที่ออกวันนี้

## ไม่ทำในรอบนี้

- ไม่แสดงตำแหน่งที่ยังไม่มีผู้ดำรง
- ไม่ให้เลือกดูย้อนหลังตามวันที่
- ไม่แก้ไขข้อมูลในหน้านี้
- ไม่มีการพิมพ์หรือ export
- ไม่แสดงบทบาทจากคำสั่งแต่งตั้ง เช่น กรรมการชุดต่าง ๆ

## สิ่งที่ถือว่าล้มเหลว

ถ้าหน้านี้แสดงคนละคนกับที่เอกสารผูกจริง หน้านี้จะใช้เช็คไม่ได้เลย แม้หน้าจะทำงานได้ตามปกติก็ตาม

## Approaches

- **A. backend ใช้ `pickHolder` ตัวเดียวกับที่ใช้ผูกเอกสาร (Kit เลือกแบบนี้)** ผลลัพธ์ตรงกับการผูกเอกสารเสมอ และถ้าวันหลังกฎการเลือกผู้ดำรงเปลี่ยน หน้านี้ก็เปลี่ยนตามเอง ข้อแลกเปลี่ยนคือตำแหน่งหนึ่งแสดงคนเดียว คือคนที่ระบบเลือก
- B. กรองด้วย SQL `starts_on ≤ วันนี้ ≤ ends_on` ตัดทิ้ง เพราะกฎต่างจาก `pickHolder` เช่น ไม่ได้ให้ข้อมูลที่เจ้าหน้าที่กรอกเองมาก่อนข้อมูล sync จึงอาจแสดงคนละคนกับที่เอกสารผูก
- C. หน้าเว็บคำนวณเองใน TypeScript ตัดทิ้ง เพราะต้องเขียนกฎซ้ำอีกชุด ซึ่งวันหนึ่งจะไม่ตรงกัน

## สิ่งที่ Kit ตัดสินใจแล้ว

- ตำแหน่งในหน้านี้คือตำแหน่งบริหารในองค์กร (ข้อมูลจาก `position_holders`)
- ทุกคนที่ล็อกอินเปิดหน้านี้ได้ รวมถึง VIEWER
- อยู่ในเมนูหลักแถบบน ต่อจาก "ค้นหาข้อมูล"
- แต่ละแถวแสดงตำแหน่ง, ชื่อ-สกุลที่มีตำแหน่งวิชาการนำหน้า, วันเริ่ม, วันสิ้นสุด และที่มาของข้อมูล
- เรียงตามลำดับชั้น: คณบดี → รองคณบดี → ผู้ช่วยคณบดี → หัวหน้า → อื่น ๆ
- หน้านี้ดูได้อย่างเดียว มีลิงก์ไปแก้ในหน้าข้อมูลอาจารย์

## Backend

`GET /api/v1/position-holders/current` ไม่ใส่ `requireRole` เพื่อให้ทุก role เรียกได้

1. โหลดข้อมูลด้วย `loadPositionHolders(db)` ตัวเดียวกับที่ใช้ผูกเอกสาร ฟังก์ชันนี้ข้ามคนที่ไม่ active ให้อยู่แล้ว และคืนค่าเป็น map ที่มี `positionKey` เป็น key
2. วันนี้ใช้วันที่ตามเวลา Asia/Bangkok แบบไม่มีเวลา
3. แต่ละ key เรียก `pickHolder(list, &today)` ถ้าได้ nil ให้ข้าม (ไม่แสดงตำแหน่งว่าง) และข้าม key ที่ `committeeRoleOnly` เป็นจริงด้วยเพื่อกันพลาด
4. เติมชื่อจาก directory โดยต่อคำนำหน้า (รวมตำแหน่งวิชาการ) ชื่อ และนามสกุล แบบเดียวกับ `directoryPersonAPI`
5. ข้อมูลแต่ละแถวมี `positionTitle`, `directoryUserId`, `fullName`, `startsOn`, `endsOn`, `source`
6. เรียงตาม `positionRank(title)` ก่อน ตามด้วยชื่อตำแหน่ง แล้วตามด้วยชื่อคน
   - ค่า rank: คณบดี = 0, ขึ้นต้นด้วย "รองคณบดี" = 1, ขึ้นต้นด้วย "ผู้ช่วยคณบดี" = 2, ขึ้นต้นด้วย "หัวหน้า" = 3, อื่น ๆ = 4
   - เทียบจาก `positionKey` และต้องเช็ค "รองคณบดี" กับ "ผู้ช่วยคณบดี" ก่อน "คณบดี"

## Frontend

- หน้า `src/app/positions/page.tsx` เพิ่มเมนูใน `app-shell.tsx` ป้ายเต็ม "บุคลากรโดยตำแหน่ง" ป้ายสั้น "ตำแหน่ง"
- ตารางมีคอลัมน์ ตำแหน่ง | ชื่อ-สกุล | วันเริ่ม | วันสิ้นสุด | ที่มา และมีบรรทัดบอก "ข้อมูล ณ วันที่ …" ใต้หัวหน้า
- วันที่แสดงแบบไทย ถ้าไม่มีค่าแสดง "—"
- ป้ายที่มาของข้อมูล: SYNC = "ระบบวิทยาลัย", MANUAL = "กรอกเอง", LEARNED = "จากการตรวจเอกสาร"
- ถ้าไม่มีข้อมูลเลย แสดงข้อความบอกว่ายังไม่มีข้อมูล และบอกว่าข้อมูลมาจาก sync หรือการกรอกในหน้าข้อมูลอาจารย์
