# ชื่อจาก OCR ที่ไม่พบในระบบ: ข้ามไว้ก่อน แล้วผูกอัตโนมัติทีหลัง (design แบบสั้น)

วันที่ 15 พ.ย. 2026 · ขนาดงาน: เปลี่ยนเล็กถึงกลาง ไม่มี migration

## เจตนา

ชื่อในคำสั่งที่ระบบผูกกับบุคลากรไม่ได้ ส่วนใหญ่เป็นคนนอกคณะที่ไม่อยู่ในรายชื่อ sync ตอนนี้แค่ชื่อเดียวก็ทำให้เอกสารยืนยันอัตโนมัติไม่ได้ และต้องรอคนมาจัดการ ลูกค้าต้องการให้ข้ามชื่อพวกนี้ไปเลย แต่ยังเก็บไว้และค้นหาเจอเหมือนเดิม เมื่อ sync แล้วคนนั้นเข้ามาอยู่ในระบบ ให้ผูกให้เอง

## เป้าหมาย

- แถวที่มีชื่อแต่ผูกไม่ได้ ไม่นับเป็นงานค้าง และไม่ขวางการยืนยันอัตโนมัติ
- หน้าตรวจเอกสารยังแสดงชื่อพวกนี้ พร้อมป้าย "ไม่อยู่ในระบบ"
- ค้นหาเจอเป็น "ชื่อในเอกสาร (ยังไม่ผูก)" เหมือนเดิม (มีอยู่แล้ว ไม่ต้องแก้)
- เมื่อมีคนใหม่เข้าระบบ ผูกชื่อที่ตรงเป๊ะในทุกเอกสาร รวมเอกสารที่ยืนยันแล้ว และลงประวัติการแก้ไขของเอกสาร
- เอกสารที่ค้างรอตรวจอยู่เพราะเหตุนี้อย่างเดียว ถ้าผ่านเงื่อนไขอื่นครบ ให้ยืนยันอัตโนมัติ (เฉพาะเมื่อเปิดการยืนยันอัตโนมัติไว้)

## ไม่ทำในรอบนี้

- ไม่มีตารางใหม่หรือคอลัมน์ใหม่
- ไม่มีหน้ารายชื่อบุคคลภายนอก

## สิ่งที่ถือว่าล้มเหลว

- เอกสารที่ยืนยันแล้วถูกเปลี่ยนคนในแถวที่ผูกไว้แล้ว ตามกฎแล้วต้องเติมได้เฉพาะแถวที่ยังว่าง
- ชื่อที่แค่ใกล้เคียงถูกผูกเอง (ผิดกฎ EXACT/ALIAS เท่านั้น ใน `CLAUDE.md`)
- ระบบที่ยังไม่มีรายชื่อบุคลากรเลย ยืนยันเอกสารทุกฉบับให้เอง

## Approaches

- **A. ไม่เพิ่มคอลัมน์ ดูจากสภาพของแถว (Kit เลือกแบบนี้)** "คนนอก" คือแถวที่ `TRIM(full_name) <> ''` และ `directory_user_id IS NULL` พอผูกได้ป้ายก็หายเอง ไม่ต้องล้างค่าอะไร
- B. เพิ่มคอลัมน์ `is_external` ไม่เลือก เพราะต้องตั้งกลับเป็น false ทุกที่ที่มีการผูกคน และถ้าพลาดที่ใดที่หนึ่งป้ายจะค้าง

## สิ่งที่ Kit ตัดสินใจแล้ว

- ข้ามทุกชื่อที่ระบบผูกเองไม่ได้ ทั้ง NOT_FOUND, FUZZY และ AMBIGUOUS
- คนตรวจยังเห็นชื่อพวกนี้ มีป้าย "ไม่อยู่ในระบบ" และไม่นับเป็นงานค้าง
- ใช้แถวเดิมใน `appointments` ไม่มีตารางใหม่
- ผูกย้อนหลังทุกเอกสาร รวมที่ยืนยันแล้ว เฉพาะชื่อที่ตรงเป๊ะ (EXACT หรือ ALIAS)
- เอกสารที่ค้างอยู่ตอนนี้ให้เช็คใหม่ ถ้าผ่านให้ยืนยันอัตโนมัติ

## Calls ที่ Claude ตัดสินใจเอง (Kit แก้ได้)

- **แถวโดยตำแหน่งที่ยังไม่มีผู้ดำรงยังบล็อกเหมือนเดิม** แถวพวกนี้ไม่มีชื่อ จึงไม่ใช่คนนอก แต่คือข้อมูลผู้ดำรงตำแหน่งที่ยังขาด
- **ถ้ายังไม่มีรายชื่อบุคลากรเลย (DIRECTORY_EMPTY) ยังบล็อก** ป้องกันกรณียังไม่ได้ sync แล้วระบบยืนยันทุกฉบับให้เอง
- **ชื่อ FUZZY ยังแสดงคำแนะนำ "ใช่คนนี้ไหม"** แต่ไม่นับเป็นงานค้าง
- **ผูกย้อนหลังตอนเจ้าหน้าที่เพิ่มอาจารย์เองด้วย** ไม่ใช่แค่หลัง sync
- **เอกสารที่ยืนยันแล้ว ระบบแตะได้แค่แถวที่มีชื่อและยังว่างเท่านั้น** ไม่ถอด FUZZY ไม่เปลี่ยนแถวโดยตำแหน่ง และไม่แก้แถวที่ผูกแล้ว
- **การผูกย้อนหลังลง `DocumentRevision` หนึ่งแถวต่อหนึ่งชื่อ** `FieldKey` เป็น `appointment_link`, `OldValue` เป็นชื่อในเอกสาร, `NewValue` เป็นชื่อบุคลากรที่ผูก และ `ChangedBy` เป็น `"sync"` หรือชื่อผู้ใช้ที่เพิ่มอาจารย์

## Backend

1. **`readyToAutoConfirm`** (`document_status.go`) นับเป็นงานค้างเฉพาะแถวที่ยังไม่ผูกและเข้าเงื่อนไขข้อใดข้อหนึ่ง
   - ไม่มีชื่อ (แถวโดยตำแหน่ง)
   - `name_match_method = DIRECTORY_EMPTY`
2. **ผูกย้อนหลัง** แยกฟังก์ชันใหม่ `linkExternalNames(db, changedBy string) (linkedDocs []uint, err error)`
   - หาแถวที่มีชื่อและยังว่าง ในเอกสารทุกสถานะยกเว้นยกเลิก
   - เทียบด้วย `matchDirectoryUser` ผูกเฉพาะ EXACT/ALIAS
   - เขียน `DocumentRevision`
   - `refreshPendingMatches` ตัวเดิมยังทำงานกับเอกสารที่ยังไม่ยืนยันตามเดิม
3. **ตัวเรียกใช้**
   - หลัง sync (`sync.go` ต่อจาก `refreshPendingMatches`)
   - หลัง `createDirectoryUser` สำเร็จ
4. **เช็คเอกสารที่ค้างใหม่** หลังผูกย้อนหลัง และตอน backend เริ่มทำงานหนึ่งครั้ง (สำหรับเอกสารที่ค้างอยู่แล้ว) ให้เรียกตัวยืนยันอัตโนมัติที่มีอยู่กับเอกสารที่ยังรอตรวจ
   - ใช้ `autoConfirmEnabled` กับ `readyToAutoConfirm` ชุดเดิม
   - ผู้สร้างแผนต้องหาตัวที่ยืนยันอัตโนมัติอยู่ตอนนี้ แล้วเรียกตัวเดียวกัน ห้ามเขียนกฎซ้ำ

## Frontend

- `src/lib/member-review.ts`: แถวที่มีชื่อแต่ยังไม่ผูก (ไม่ใช่ DIRECTORY_EMPTY) แสดงป้าย "ไม่อยู่ในระบบ" เป็นโทนกลาง ไม่ใช่สีแดง ส่วน FUZZY ยังโชว์ตัวเลือกแนะนำเหมือนเดิม
- `src/components/document-workspace.tsx`: ตัวนับ "ยังไม่ผูก" และแถบเตือนนับเฉพาะแถวโดยตำแหน่งที่ยังว่าง และกรณี DIRECTORY_EMPTY ส่วนชื่อคนนอกแสดงเป็นตัวนับแยก "ไม่อยู่ในระบบ N" ที่ไม่ใช่สีเตือน ปุ่ม "+ เพิ่มคนที่ไม่พบในระบบ" ยังอยู่

## เทสต์

- **`readyToAutoConfirm`:** ชื่อคนนอก (NOT_FOUND/FUZZY/AMBIGUOUS) ผ่าน แถวโดยตำแหน่งที่ว่างไม่ผ่าน DIRECTORY_EMPTY ไม่ผ่าน (แก้ case "unlinked name" ในเทสต์เดิมให้ตรงกฎใหม่)
- **`linkExternalNames`:**
  - เอกสารที่ยืนยันแล้ว ชื่อที่ตรงเป๊ะถูกผูก และมี revision
  - ชื่อที่แค่ใกล้เคียงไม่ถูกผูก
  - แถวที่ผูกคนอื่นไว้แล้วไม่ถูกเปลี่ยน
  - แถวโดยตำแหน่งในเอกสารที่ยืนยันแล้วไม่ถูกแตะ
  - เอกสารที่ยกเลิกไม่ถูกแตะ
- **การเช็คเอกสารค้าง:** เอกสารรอตรวจที่ติดเพราะชื่อคนนอกอย่างเดียว ถูกยืนยันเมื่อเปิดการยืนยันอัตโนมัติไว้ และไม่ถูกยืนยันเมื่อปิดไว้
- **Frontend:** `matchState` และฟังก์ชันนับใน `member-review.ts`
