# งานต่อจากการทบทวนฐานข้อมูล DocFlow

ทบทวนวันที่ 17 พฤศจิกายน 2569 สำหรับระบบที่มีเจ้าหน้าที่หลายคนและมีงาน OCR, sync และแจ้งเตือนทำงานเบื้องหลัง รายการด้านล่างเป็นงานที่รอทำ

## ก่อนเปิดใช้งานจริง

- [ ] **กันผล OCR เก่าเขียนทับเอกสารรุ่นใหม่** ตรวจสถานะอีกครั้งหลังล็อกแถวตอนอัปโหลดทับ และตรวจรุ่นงานใน worker ก่อนเขียนผลสำเร็จ ผลล้มเหลว หรือคิว retry ทดสอบโดยค้างงาน OCR ไว้ สลับไฟล์ แล้วส่งผลจากงานเดิม ผลและสถานะของไฟล์ใหม่ต้องไม่เปลี่ยนจากงานเดิม ดู [การอัปโหลดทับ](../../../backend/api_handlers.go#L958) และ [การบันทึกผล OCR](../../../backend/document_queue_store.go#L92)
- [ ] **แจ้งเตือนเฉพาะคำสั่งที่ยืนยันแล้ว** ใช้สถานะ `CONFIRMED` ตรงกันตอนสร้างรายการ แสดงรายการ และส่งอีเมล ตรวจสถานะอีกครั้งภายใต้ row lock ก่อนส่ง ทดสอบร่างที่มีวันหมดวาระและรายการค้างของคำสั่งที่ถูกส่งกลับหรือยกเลิก ดู [การแจ้งเตือน](../../../backend/expiry.go#L16)
- [ ] **รักษาหลักฐานเมื่อเลิกใช้เอกสาร** จำกัดลบถาวรไว้สำหรับข้อมูลทดสอบตามนโยบายที่ตกลง และใช้การยกเลิกกับคำสั่งที่เคยยืนยัน ตรวจประวัติการยืนยันก่อนลบ แม้สถานะปัจจุบันกลับมาเป็นร่างแล้ว ทดสอบว่าเปิดดูชื่อและผู้ยืนยันแต่ละรอบได้หลังยกเลิก ดู [การลบ](../../../backend/api_handlers.go#L560) และ [ตารางประวัติยืนยัน](../../../backend/migrations/0002_confirmation_names.sql#L13)
- [ ] **ใช้กฎวาระเดียวกันจากทุกหน้าจอ** ใช้ตัวตรวจช่วงทับซ้อนร่วมกัน และปิดวาระเดิมกับเพิ่มวาระใหม่ใน transaction เดียว จัดให้การเขียนตำแหน่งเดียวกันตรวจช่วงและบันทึกทีละรายการ ทดสอบการบันทึกช่วงซ้อนผ่านทั้งสองหน้าจอและการบันทึกพร้อมกัน ดู [การตรวจช่วงวาระ](../../../backend/position_holders_api.go#L120) และ [การตั้งผู้ดำรงตำแหน่ง](../../../backend/position_holders_api.go#L208)

## งานต่อหลังปิดรายการข้างต้น

- [ ] **กำหนดพฤติกรรม Drive หลังลบเอกสาร** ถ้าอนุญาตให้นำเข้าใหม่ ให้ลบแถว `drive_imported_files` ใน transaction เดียวกับเอกสาร ถ้าต้องการข้ามไฟล์ต่อไป ให้บันทึกสถานะว่าลบแล้วอย่างชัดเจน ทดสอบลบเอกสารแล้วรัน sync ซ้ำ ดู [ตาราง mapping](../../../backend/migrations/0001_clean_baseline.sql#L269) และ [การตรวจไฟล์ที่เคยนำเข้า](../../../backend/drive_automation.go#L612)
- [ ] **ให้การค้นทำงานต่อได้เมื่อไฟล์ OCR หายหรือเสีย** คืนผลจาก DB และ OCR ที่อ่านได้ พร้อมบันทึก ID ของเอกสารที่มีปัญหา ทดสอบค้นชื่อเรื่องหรือเลขคำสั่งเมื่อเอกสารอื่นมีไฟล์ OCR เสีย วัดเวลาค้นด้วยชุดข้อมูลจริงก่อนเพิ่มดัชนีข้อความ ดู [การค้น OCR](../../../backend/extraction_search.go#L72)
- [ ] **ทดสอบกู้คืน DB และไฟล์เป็นชุดเดียวกัน** บันทึกขั้นตอนกู้ MySQL กับ volume เอกสารจากชุดสำรองเดียวกัน แล้วทดสอบเปิดไฟล์ต้นฉบับ ผล OCR และประวัติยืนยันบนฐานที่กู้คืน ดู [คู่มือสำรองข้อมูล](../../../DEPLOY_PODMAN.md#15-backup)

## โครงสร้างที่ใช้ต่อได้

ใช้ MySQL กับ `documents` เป็นระเบียนหลัก เก็บรหัสบุคคลแยกจากชื่อ ณ รอบยืนยัน และใช้ hash กันไฟล์ซ้ำ การเก็บ PDF และ OCR JSON นอก MySQL ลดขนาดฐานและทำให้ต้องดูแลการกู้คืนไฟล์ร่วมกับฐานข้อมูล ประวัติยืนยันแบบ JSON เหมาะกับการเปิดทั้งรอบ หากต้องทำรายงานข้ามรอบตามบุคคลจึงประเมินการแยกรายชื่อเป็นตาราง
